Color Spaces & the Fold Pipeline · Lesson 5

The round trip

linear → display → linear → screen, pass by pass. Everything so far, assembled.

You have all the pieces now: two encodings (L1), the depth buffer (L2), the routing (L3), and where the color space lives in the data (L4). This lesson spends them. Question 5 — why linear → display → linear → screen? — is really four questions, one per arrow. We'll answer each with the same tool: a fragment must be encoded to match the buffer it writes into (the destination-encoding rule), and the fold needs a gamma buffer.

1 · The whole trip, annotated

Pass 1 Pass A Pass B Pass C Pass 5 opaque seed fold out tonemap LINEAR ──▶ DISPLAY ──▶ DISPLAY ──▶ LINEAR ──▶ SCREEN scene encode add prims decode encode linear→display (gamma blend) display→linear linear→screen + RGB555 quantize

Two things to notice before the details. First, DISPLAY and SCREEN are the same amber — the same gamma space (your L1 payoff), just at two stops. Second, the trip is a bracketed gamma excursion: it leaves linear only for the fold, then returns, so the fold is the only thing that happens in gamma.

2 · One row per arrow

Grounded in the consumer's own header, CombatDisplaySpaceComposite.gd:25–36:

PassencodingWhy this encoding
1 · opaque linear Forward+ renders the scene in linear HDR — lighting math must be linear (L1). Units run pow(2.2) to land here. Depth written here (L2).
A · seed linear→display Copy the opaque scene into the scratch, encoding to display, so the scratch is a gamma-encoded copy of the background. Coverage α seeded to 0. Now the fold has a gamma canvas.
B · fold display Draw the flagged prims (resolved display colors, L4) with hardware add/sub/mix, in OTDepthPrimOrder, depth-tested vs. the opaque depth. Both operands are gamma → the add is a gamma add (L4). This is the PSX look. No encoding change here — just the blend.
C · out display→linear Resolve the scratch back into the scene, decoding to linear (+ RGB555 quantize, discard untouched pixels). The folded result re-enters the engine's linear pipeline so it tonemaps like everything else.
5 · tonemap linear→screen Map linear HDR down to displayable range and encode to sRGB for the monitor. The monitor expects gamma at its input (L1). Covered next lesson.

3 · So, the four "why"s in one breath

Why leave linear (A)? Because adding PSX additives in linear is *the defect* — the fold must be a gamma add, which needs a gamma buffer. Why stay display (B)? Because that's where the blend happens; the whole excursion exists for this one step. Why go back to linear (C)? So the result rejoins the engine's linear pipeline — otherwise the tonemap, which expects linear, would mangle it. Why encode to screen (5)? Because the monitor is a gamma device. Leave → do the one gamma thing → come back → hand off to the display.

4 · Where the color actually changes (your round-trip question)

You asked earlier whether display→linear changes the color or is "just re-encoding." Now you can see it in the table: the encode/decode arrows (A and C) are faithful — same light, different representation. The color only moves in two places:

• Pass B — the gamma-domain add. This is the intended change (the PSX look). A linear-domain add of the same prims would give different numbers; that difference is the entire point.

• Pass C's RGB555 quantize — a deliberate lossy step (PSX 5-bit color). The decode sitting next to it is lossless; the quantize is the loss.

Everything else is a change of coordinates, not of color.

5 · The honest edges

Three things this lesson is not glossing

• Seed clamps HDR. The opaque scene is linear HDR (can exceed 1.0); the display scratch is UNORM [0,1]. Encoding in Pass A clamps anything over 1 — a real change, but a range effect, not the decode.

• Pass B in display is guaranteed for the particle fold, open for engine-drawn units. The real unit material would first have to suppress its line-923 pow (L4 / open question #1). Don't assume it's free.

• Linear tonemap is mandatory. The header says it: "Run under Linear tonemap (ACES/AgX corrupt the add)." Why an S-curve tonemap would break the fold is exactly Lesson 6.
